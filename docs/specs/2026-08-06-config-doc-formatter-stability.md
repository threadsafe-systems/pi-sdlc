## 1. Outcome and boundaries

For every top-level persisted configuration value, `config-doc` emits the byte-exact `JSON.stringify` token inside a valid CommonMark code span whose delimiter cannot collide with a backtick run inside that token. This closes #177's nested-backtick malformed-span defect while preserving the compact JSON-order key list.

The contract does not claim canonical stability under every Markdown formatter. It proves delimiter non-collision, exact value preservation, deterministic generation, and absence of the known malformed one-backtick shape. No Markdown parser/formatter or runtime dependency is added.

Unchanged: configuration schemaVersion 3, CLI commands/exits/envelopes, check/write state machine, collision and symlink behavior, readiness/startup behavior, canonical JSON, config authority, and setup integration.

## 2. Render-format identity

- `CURRENT_SENTINEL_VERSION` is `v2`.
- `SUPPORTED_SENTINEL_VERSIONS` is exactly `{"v1", "v2"}` for this release.
- The existing fingerprint formula is unchanged: `sha256hex(CURRENT_SENTINEL_VERSION + NUL + canonicalJson(config))`.
- A well-formed v1 sentinel remains recognized generated output. Relative to the v2 expected render it is stale; `write` regenerates it to v2 without `--force`.
- Unsupported/malformed sentinels remain collisions.

The original self-documentation Specification is amended in this Spec revision to rev 3: its §12 envelope example names v2; §13 names v2 current and `{v1,v2}` supported while preserving the version lifecycle; §14 requires adaptive code spans for exact key values. Its revision history cites #177 and this Specification's gate. The rev-3 text participates in this same Spec panel and becomes approved only when this gate is human-approved.

## 3. Adaptive code-span contract

Let `value = JSON.stringify(config[key])`. For schema-valid persisted top-level values, `value` is a defined string.

1. Find every maximal contiguous run of U+0060 BACKTICK in `value`.
2. Let `maxRun` be the greatest run length, or zero when no run exists.
3. Let `delimiter` be U+0060 repeated `maxRun + 1` times.
4. Render the value span as `delimiter + value + delimiter`, with no escaping, stripping, padding, or normalization.
5. Keep the existing list shape: `- **<key code span>** = <adaptive value code span>`.

Because JSON tokens begin and end with JSON syntax rather than a backtick, CommonMark boundary-space normalization does not apply. The chosen delimiter cannot occur inside `value` by construction.

The key name remains rendered by the existing fixed one-backtick span because schema-valid top-level keys contain no backticks. Only arbitrary serialized values use the adaptive helper.

## 5. Error and edge semantics

- A serialized value with no backticks uses a one-backtick delimiter, preserving the existing rendering for ordinary values.
- Runs of one, two, or more backticks force delimiters of two, three, or greater length respectively.
- Multiple runs use the greatest run, irrespective of order.
- Empty strings, booleans, numbers, null, arrays, and objects preserve their exact `JSON.stringify` token.
- A render-format v1 file is recognized stale, never refused.
- A v2 file whose body is formatter-mutated remains recognized stale and is regenerated by `write`.
